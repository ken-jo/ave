# 브라우저와 터미널 작업 공간

공유 탭 제어와 두 터미널 레인을 설명하는
[영문 가이드](../../guides/browser-terminal-workspace.md)의 한국어 미러입니다.
현행 기준은 [아키텍처](../../architecture/architecture.md#browser-and-terminal-workspace)와
[권한 설계](../../architecture/permission-policy-design.md#shared-browser-control-and-effects)입니다.
실제 네이티브 조작과 공급자 인증의 최종 검증은 남아 있습니다. 이 설명만으로
릴리스나 측정한 성능 개선이 입증되는 것은 아닙니다.

## 작업 공간을 함께 유지하기

채팅·브라우저·터미널을 함께 열어 둘 수 있습니다. 브라우저나 터미널 머리글의
패널 토글로 별도 채팅을 열고, 사이드와 메인 사이에서 패널을 옮겨도 페이지와 두
터미널 레인은 유지됩니다. 패널의 채팅을 닫는 것과 실제 탭을 닫는 것은 다릅니다.

명시한 탭이 우선합니다. 패널 채팅은 지정하지 않으면 자신의 연결된 화면을,
연결되지 않은 대화는 창의 해당 종류 활성 화면을 대상으로 합니다. 연결된 탭이
사라지면 다른 탭으로 바꾸지 않고 실패합니다. 창의 브라우저 목록을 볼 수 있다고
다른 대화가 소유한 탭을 제어할 수 있는 것은 아닙니다.

## 브라우저 탭 함께 쓰기

| 상태 | 의미 |
| --- | --- |
| Human (`human`) | 일반 사용자 제어 상태입니다. 에이전트 변경에는 범위가 정해진 호스트 권한이 필요합니다. |
| Agent active (`agent-active`) | 호스트가 이 대화에 제어권을 주었으며 각 동작의 권한 검사는 계속 적용됩니다. |
| Human paused (`human-paused`) | 사용자가 넘겨받거나 Stop을 눌렀습니다. 명시적 Resume 전까지 에이전트 변경이 중지됩니다. |

1. 패널 채팅에 보이는 페이지 작업을 요청하거나 `browser_tabs`의 탭을 지정합니다.
   에이전트가 새 탭을 만들 수도 있으며 기본적으로 백그라운드에 열립니다.
2. 출처 승인이 나오면 확인합니다. 출처는 사이트의 스킴·호스트·포트를 구분합니다.
   현재 출처 허용은 다른 팝업 출처나 카메라 권한을 허용하지 않으며 전체 브라우저
   네트워크 방화벽도 아닙니다.
3. 브라우저 UI에서 이동하거나 Stop을 누르거나 사람의 개입으로 식별되는 페이지
   입력으로 넘겨받습니다.
   에이전트 변경은 계속 중지되며 읽기 전용 관찰은 일반 정책에 따라 가능합니다.
4. 다시 맡길 때 신뢰한 브라우저 UI의 Resume을 누릅니다. 도구나 다음 턴이 대신
   재개하지 않습니다. 넘겨받기 전 승인은 새 제어 세대에서 필요한 승인을 대체하지
   못합니다.

세 상태 모두 브라우저 기본 샌드박스와 컨텍스트 격리를 유지합니다. 모드는
에이전트 권한을 바꾸며 브라우저 기본 격리를 끄지 않습니다.

네이티브 마우스에는 구분 한계가 있습니다. 사람이 에이전트가 보내기로 한 클릭과
같은 시점·좌표·버튼·단계로 클릭하면 둘을 구분할 수 없습니다. 그 밖에 관찰된 입력
불일치는 에이전트를 중지합니다. 이 마우스 이벤트의 모호함과 무관하게 확실히
넘겨받으려면 브라우저 UI의 Stop을 사용하세요.

## 어떤 탭이 남는지 알기

에이전트가 만든 탭은 현재 제어권과 별도로 생성자를 기억합니다. 턴이 끝나도
검토·인계를 위해 남고, 권한이 있는 명시적 닫기 요청으로 닫습니다. 사용자 탭을
빌린 에이전트의 닫기 요청은 연결만 해제하고 탭을 남겼다고 알립니다. 사용자가
브라우저 UI에서 닫으면 실제 탭을 닫습니다.

대화 범위의 `browser_tabs`는 호출자의 직계 자식 에이전트 탭을 포함할 수 있습니다.
이는 실제 직계 부모 관계이며 같은 창의 모든 하위 대화를 뜻하지 않습니다.
목록이 제어 권한을 주지 않습니다. 소유 탭은 생성자·생성자의 직계 부모·직계
자식이 현재의 독점 임대 조건 안에서 접근할 수 있습니다. 형제·손자·무관한 대화는
이 권한을 물려받지 않습니다. 네이티브 팝업은 소유 창 안에서 추적되며 일반
탭 카드가 없을 수도 있습니다. 팝업의 출처 승인과 자식 창 격리는 별도로 유지하고,
소유 창이 닫히면 자원을 해제합니다.

## 페이지 조작과 파일 업로드

에이전트는 페이지 구조·이미지 캡처, 이동, 클릭, 입력, 지원 키 누르기를 사용할 수
있습니다. 추가 도구는 대상 위로 포인터 이동, 두 참조 사이 드래그, 네이티브 단일
선택, 참조 대상 스크롤을 제공합니다. 페이지 구조 스냅샷이 요소 참조를 제공합니다.
참조는 현재 문서에 속하며 오래되거나 지원하지 않는 대상은 명시적으로 실패합니다.
선택은 최종 값을 확인합니다.
이미지는 픽셀·바이트 한도가 있는 뷰포트만 캡처합니다. 전체 페이지 픽셀을
신뢰할 수 있다는 증명이 없어 전체 캡처 요청은 캡처 전에 명시적으로 실패합니다.

| 도구 | 입력 |
| --- | --- |
| `browser_hover` | `ref` |
| `browser_drag` | `sourceRef`, `targetRef` |
| `browser_select` | `ref`, `value`; 네이티브 단일 선택만 지원 |
| `browser_scroll` | `ref`, `direction` (`up`, `down`, `left`, `right`), `pixels` |
| `browser_upload` | `ref`; 승인된 네이티브 선택기를 엶 |
| `browser_screenshot` | 뷰포트만 지원; `fullPage` 생략 또는 `false` |

각 도구는 `browser_tabs`의 `tabId`를 선택적으로 받습니다. 알 수 없는 필드는 거부합니다.

일반 포인터·슬라이더 드래그는 네이티브 누름과 뗌 수신을 요구합니다. HTML5
드래그는 브라우저가 가로챈 한도 있는 텍스트로 enter/over/drop을 수행하며 일반
마우스 뗌 요청의 응답만으로 놓기를 증명하지 않습니다. 파일·호스트 경로는 받지
않으며 업로드 권한도 부여하지 않습니다. 페이지나 제어권이 바뀌면 취소하고,
앞에서 설명한 동시 클릭의 출처 구분 한계도 유지합니다. 에이전트에 임의 스크립트나
프로토콜 명령을 노출하지 않습니다.

목적지에 놓기 전에 출발 드래그 취소와 가로채기 해제를 확인합니다. 놓기를 전송한
뒤 응답이 유실되면 효과가 이미 발생했을 수 있으므로 페이지를 확인한 뒤 다시 시도하세요.

업로드는 `browser_upload({tabId?, ref})`로 현재 파일 입력 대상을 지정합니다.
사용자는 그 한 번을 명시적으로 승인한 뒤 목적지를 보여 주는 네이티브 선택기에서
파일을 고릅니다. 에이전트는 호스트 파일 경로를 제출할 수 없습니다. 작성창 첨부는
웹사이트 업로드 승인이 아닙니다. 선택기를 취소하면 파일을 보내지 않으며 이동·
제어권 인계·문서 변경으로 대상이 오래되어도 취소합니다. 결과는 비밀이 아닌 파일
이름·개수·크기·상태만 알리고 호스트 경로는 공개하지 않습니다.

호스트는 한도가 있는 비공개 읽기 전용 파일 사본을 도구 반환 뒤에도 선택한
입력·문서에 묶어 유지하고 교체·이동·게스트 파괴·종료 시 선택을 해제합니다. 이
경계에서 실제 브라우저 읽기 동작은 네이티브 검증이 남아 있습니다. 출처를 모르는 비정상 종료 잔여물은
자동으로 재사용하거나 삭제하지 않습니다. 파일 검사, 불변 사본, 임대 식별자, 저장 한도는
[업로드 권한 계약](../../architecture/permission-policy-design.md#shared-browser-control-and-effects)을 따릅니다.

## 일반 브라우저 제어

브라우저 UI는 북마크, 한도가 있는 방문 기록과 삭제, 페이지 찾기, 확대/축소,
사이트 기능 권한, 다운로드 상태, 탭 카드 미리보기를 제공합니다. 북마크와 기록은
자격 증명을 주소에 포함하지 않은 검증된 HTTP(S) URL을 받습니다. 로컬 다운로드
정보가 에이전트에 자동 공개되지는 않습니다.

카메라·마이크·위치·알림은 검증된 현재 메인 프레임 요청에 대해 명시적인 사이트
결정이나 신뢰한 확인 UI를 따릅니다. 전체 화면은 안전한 종료 UI가 없어 사용할 수
없으며 저장된 허용으로도 켤 수 없습니다. 알 수 없는 권한은 거부하며 iframe 출처와 리다이렉트는 다른 출처의
허용을 물려받지 않습니다. 다운로드는 네이티브 저장 대화상자로 위치를 묻고,
요청 빈도 제한을 유지하며 저장한 파일을 자동으로 열지 않습니다.

보이는 창의 보이는 카드만 미리보기를 요청합니다. 패널을 숨기거나 언마운트하면
새 요청을 멈추고 숨김·이동·닫기 뒤 늦게 도착한 결과는 버립니다. 창별 캡처 빈도와
동시 실행을 제한하며 늦은 결과는 캐시에도 넣지 않습니다. 렌더러만 완료 때도
적격인 카드의 이미지를 캐시하고 메인은 캡처 제한·무효화 상태만 관리합니다.
미리보기 때문에 탭을 포커스·이동·재생성하지 않습니다.
자원 사용 개선을 주장하려면 실제 캡처 횟수와 게스트 동작의 실행 증거가 필요합니다.

## 내 브라우저와 터미널의 세션 선택

사용자 소유 브라우저 탭과 호스트 터미널은 같은 세 가지 세션 선택을 사용합니다. 첫 적격 동작에서 **이 세션 모두 허용**, **오토**, **모두 질문**을 고릅니다. 오토는 일반 위험도가 아니라 사용자 요청·현재 작업 단계와 대상 탭/페이지 또는 명령의 논리적 일치만 확인하며, 실패·오류·의도 부족·불확실성은 일반 승인 카드로 보냅니다. 모두 질문이 기본이며, 카드를 닫으면 실행하지 않습니다. 선택은 대화 세션과 표면별로 따로 메모리에만 두고 세션 종료 시 지웁니다. 전역 모드나 일반 기억 승인이 이를 대신하지 않으며, 헤드리스는 항상 거부합니다. 입장 차단·deny 규칙·실제 다른 주체/오염·유출 강제 조건, 자격증명 입력·결제·되돌릴 수 없는 제출 보호는 모든 선택에 유지됩니다. 직접 입력한 터미널 명령은 사용자 행위로 승인 대상이 아닙니다.

[자세한 표면 계약](../../architecture/permission-policy-design.md#user-owned-surface-choices)을 참고하세요.

## 호스트 터미널과 대화의 격리 셸

보이는 터미널에는 실제 HOME과 프로필을 쓰는 사용자 호스트 셸이 있습니다. 사이드 작업 패널 터미널에는 에이전트 접근이 없습니다. 일반 대화는 자신의 격리 셸을 사용하고, 적격 터미널 패널 대화는 해당 패널의 호스트 셸에만 명령할 수 있습니다. 다른 대화의 터미널로 대신 실행하지 않습니다.

표면 선택과 별개로 실제 대화·턴·터미널 세션·셸·빈 프롬프트·물리 디렉터리·제어 세대를 확인합니다. 사용자 입력이나 Take over/Stop, 바인딩 변경과 턴 종료는 에이전트 제어 임대를 끝냅니다. 출력은 허용된 현재 턴과 블록에만 돌아오며 기존 호스트 스크롤백을 자동 공유하지 않습니다. 필요한 셸 연동이나 격리가 없으면 해당 기능을 사용할 수 없다고 알리며, 다른 터미널로 조용히 바꾸지 않습니다.

대기 시간 초과는 명령 종료나 정리 완료를 뜻하지 않습니다. [호스트 명령 제어](../../architecture/permission-policy-design.md#host-command-control)와 [격리 셸 계약](../../architecture/permission-policy-design.md#commands-typed-into-a-workspace-terminal)을 따릅니다.
