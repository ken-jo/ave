# Browser UI composition acceptance

The [browser lifetime and composition contract](../architecture/architecture.md#browser-control-and-tab-lifetime) owns page presentation. This record tracks evidence that the app UI stays above live independent pages while preserving page input, host input and retained user-page behavior. An earlier recorded run does not establish acceptance of later source or build changes.

## Evidence rules

Use real content sizes **1360×800** and **900×800** in the normal background test mode. The separately tagged OS keyboard cases run on a hosted virtual desktop and retain their actual source revision, X11 window identity, focused WebContents IDs, system input commands and asserted real content size. Each size needs its own exact test title and result artifact. Visual rows require a composed-window capture; nonvisual focus/control regressions retain raw JSON with actual native owner identity, content bounds and dispatch measurements without requiring screenshot-service access. Composed-window run metadata must identify the source revision, native application PID, window ID, measured content bounds and capture method. A composed capture must include actual UI and native page pixels without activating the app or substituting a renderer-only image. A DOM screenshot, fixture-only test or source inspection does not prove native composition or input routing.

`Pending` means no qualifying executed evidence is recorded. `Code only` means a named unit test or source check supports the implementation, without acceptance of composed pixels or native input. `Passed` requires the exact executed test and result link; visual assertions also need the actual composed PNG. `Failed` records the test result and its concrete failure. `Unavailable` records a missing environment or capability, not a pass. Record a nonintersection only when the current UI is actually open and its final bounds were measured. Historic geometry does not establish current acceptance.

For a partial overlay, check its controls, then click, wheel and type in a genuinely uncovered page region. Verify the page stays attached and live, with the same page identity and viewport unless the host pane itself is resized. A full modal backdrop, fullscreen app or full-page capture selector has **no uncovered page area**: test its own interception and exit, then page interaction after dismissal. Native OS menus, OS-first-responder keyboard routing, system IME and OS drag-and-drop need separate foreground evidence under the [native E2E policy](../../test/e2e/README.md). Background page input does not provide that evidence.
