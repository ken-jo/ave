# Authentication window chrome

[`auth-window-content.ts`](../../src/main/auth-window-content.ts) owns the shared address shell for cookie login and OAuth login, including recursively adopted popups. `authWindowChromeOptions` keeps native window controls in the same 36px row: inset traffic lights on macOS, title bar overlay controls on Windows and Linux. Neither shell has a preload or custom control IPC. Native overlay backgrounds and symbols use `TITLEBAR_COLORS`, the same light/dark tokens as the shell, and follow system-theme changes. The traffic lights have an explicit inset so their position is measurable.

The address and security icon are excluded from the drag region. The remaining title space stays draggable. The address is selectable text, and hovering it exposes the full original URL in a tooltip. Copying any selection within the address copies the full original URL, including visually elided parts. The existing `oauthWindow.address` key names the address group; connection labels name the icon, tooltip and visually hidden polite live status in both locales.

The host shell displays the initial address immediately and updates it on committed top-level navigation, including redirect destinations, and same-document navigation. Pending redirects retain the visible document identity: a remote page cannot borrow a trusted destination's address by starting then aborting a navigation. Non-HTTP(S) addresses, including `about:blank`, appear verbatim for internal or initial shell states; this does not permit non-HTTP(S) remote navigation.

The window has a minimum width of 520px. Its address text shows only the registrable domain (eTLD+1), without protocol, subdomain, path, query, fragment or port. For HTTP(S) URLs with no registrable domain, IP literals, localhost and bare public suffixes display their hostname from the URL parser, without the port. Non-HTTP(S) URLs display verbatim. All address text uses one span; a single RTL overflow rule provides a leading ellipsis for an unusually long domain, keeping its suffix visible. There are no separate path or suffix spans and no address sizing script.

The registrable domain comes from the public suffix list shipped with `tldts`, including private suffixes so separate tenants remain distinct. The locked parser is a direct runtime dependency because the host embeds its browser distribution into the isolated shell. It runs locally for each address update, without network lookup or a hand-maintained suffix table.

Dependabot opens public-suffix refresh PRs: the root `bun` entry in [the dependency update configuration](../../.github/dependabot.yml) includes all dependencies, including the pinned `tldts`, in its weekly grouped update PR. Maintainers review and merge those updates through normal CI; each accepted parser version refreshes the embedded suffix snapshot. The pinned version is reproducible, not a permanent suffix-data freeze. No runtime download updates the list.

HTTPS uses a lock; HTTP including loopback uses an amber warning diamond. Certificate failures use a crossed circle and load failures a warning triangle. Error documents display the failing domain or hostname, with the full failing URL available through hover and copy. Certificate failures are rejected and remain errors across same-document navigation; a new successfully committed document resets the indicator. The service's existing failure lifecycle still applies: non-certificate load failures reject the login and close the window, so their icon can be transient.

The remote document lives below the shell in an isolated guest. Adopted popup views start at `AUTH_TITLEBAR_HEIGHT` and resize within the remaining bounds. Remote fixed-position elements cannot cross that view boundary. The session denies all permission and device requests, including fullscreen. Shell navigation is blocked, and remote top-level navigation is restricted to HTTP(S). OAuth keeps its temporary partition, performs no remote script injection or cookie harvesting, and clears its storage on close. Cookie login retains its existing separate storage policy.

The [service tests](../../src/main/__tests__/auth-window-dedup.test.ts) cover domain-only display and hostname fallbacks, navigation, icon states, live status and popup bounds for both login kinds. The [window test](../../test/e2e/window/auth-window-chrome.spec.ts) exercises real redirects and local guest navigation, then checks domain-only rendering, full-URL hover and exact copy for both platform insets. At 520px a text range measures the visible `.com` suffix of a 63-character label. Windows/Linux native visuals still require a manual check on those platforms.

Only the isolated task windows were temporarily floated during capture to avoid the OS thumbnail transform; their production window options were unchanged, and the temporary flags were restored afterward. Traffic-light centers are y=18 in the 36px row; the rightmost control ends at x=72 and the address begins at x=104.
