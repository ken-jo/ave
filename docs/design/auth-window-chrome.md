# Authentication window chrome

[`auth-window-content.ts`](../../src/main/auth-window-content.ts) owns the shared address shell for cookie login and OAuth login, including recursively adopted popups. `authWindowChromeOptions` keeps native window controls in the same 36px row: inset traffic lights on macOS, title bar overlay controls on Windows and Linux. Neither shell has a preload or custom control IPC. The row is draggable; the security icon is excluded from dragging so its localized tooltip remains available.

The host shell displays the initial address immediately and updates it on committed top-level navigation, including redirect destinations, and same-document navigation. Pending redirects retain the visible document identity: a remote page cannot borrow a trusted destination's address by starting then aborting a navigation. The parsed host, including its port, is emphasized and cannot shrink; only the path, query and fragment elide at the end. The full address remains in its tooltip. The existing `oauthWindow.address` key names the address for accessibility; the connection labels name the icon and its tooltip in both locales.

HTTPS, HTTP including loopback, certificate failures and load failures have distinct icon shapes. Error documents display the failing address. Certificate failures are rejected and remain errors across same-document navigation; a new successfully committed document resets the indicator. The service's existing failure lifecycle still applies: non-certificate load failures reject the login and close the window.

The remote document lives below the shell in an isolated guest. Adopted popup views start at `AUTH_TITLEBAR_HEIGHT` and resize within the remaining bounds. Remote fixed-position elements cannot cross that view boundary. The session denies all permission and device requests, including fullscreen. Shell navigation is blocked, and remote top-level navigation is restricted to HTTP(S). OAuth keeps its temporary partition, performs no remote script injection or cookie harvesting, and clears its storage on close. Cookie login retains its existing separate storage policy.

The [service tests](../../src/main/__tests__/auth-window-dedup.test.ts) cover navigation, icon states and popup bounds for both login kinds. The [window test](../../test/e2e/window/auth-window-chrome.spec.ts) exercises a real redirect to a long local URL and a fixed-position page overlay, checking the host's geometry and capturing screenshots. Native title controls still need platform-specific visual verification on Windows and Linux.
