Status: proposed design, 2026-11-01; no runtime change. Product scope follows [the vision](../vision/README.md). Recommendations and release requirements below describe future work, not measured Windows guarantees.

## 1. Current holder inventory

Every Windows extension grant reaches `grantWindowsWorkerFilesystemAccess`: it admits and pins reads/writes, adds writes to reads, enforces machine/private-helper boundaries, incorporates live grants, and hands off overlapping deny obligations before the ordinary ACL grant. Read/write denies come from trusted base settings plus earlier wraps and the pending policy. Missing writable deny targets are materialized and stamped; overlapping deny globs refuse a grant. Native verification failure seals the session. Callers do not supply independent deny lists to the holder helper. [A5] [A6]

**Per-turn envelope versus process grant:** the inspected Windows worker API accepts one filesystem spec at spawn; it has no live grant-update method. HostApi checks its effect against the current recipient and captured plugin envelope, but its ACL remains live across turns, and every confined process sharing the account can reach another holder's currently granted roots. Do not describe the current OS grants as turn-scoped isolation. A consumer wanting a narrower per-turn worker envelope needs a new incarnation; implementation must inventory such consumers against the public contract, not invent an SDK policy-update API. This is a conflict with an interpretation of “per-turn envelopes” as existing native revocation, rather than a reason to widen future grants. [A1] [A2] [A11] [A12]

User hooks remain inventoried because they share the Windows bundled-process helper, but their admission/enablement follows the admitted host-shell plan, not `pluginWorkerConfinement`; D4 recommends preserving that distinction. Legacy shell-form user hooks resolve to PowerShell or Git Bash before launch. [A9] [A25]

The LibreOffice engine is out of scope: `OFFLINE_CONFINEMENT_PLATFORMS` is `{darwin, linux}`, so this work adds no Windows document-engine confinement. [A23]

The persistent conversation PTY and host shells are outside this extension inventory. Their separate shell setting and launch path remain intact. No new plugin-specific branch belongs in the host; the common process boundary carries these holders. [A10] [A13]

## 2. Proposed common spawn contract

Use one host-owned immutable launch plan per holder incarnation, selected after existing permission admission: owner identity, backend, session/generation, canonical R/W/deny objects, executable/arguments, cwd, stripped environment, transport and egress lease. Revalidate admission, root identities and the owner incarnation immediately before spawn. Backend choice is sealed with that plan. Preserve the shared filesystem admission and private-storage exclusions; a conversion error refuses that launch. These requirements carry the existing admission boundaries into the fixed spawn request. [A2] [A3] [A5]

The dedicated supervisor described in §3 owns native SDK calls. For MXC, use `spawn` from `@microsoft/mxc-sdk/v1` with this **typed** shape, not the raw CLI JSON fields:

```ts
{
  command: quotedExecutableAndArgs,
  containment: { type: "processcontainer", config: { filesystem: { enumeratePaths: admittedAncestorQueries } } },
  workingDirectory: admittedCwd,
  environment: strippedEnvironment,
  inheritDefaultEnvironment: false,
  filesystem: {
    readwritePaths: ranked.write,
    readonlyPaths: ranked.read,
    deniedPaths: ranked.deny,
    clearPolicyOnExit: true,
  },
  network: {
    egress: { default: "deny" },
    ingress: { default: "allow", hostLoopback: "allow" },
    runtimeConfig: { networkProxy: invocationProxyUrl },
  },
  ui: { disable: false, clipboard: "none", allowInputInjection: false },
}
```

The example uses identity-less proxying: WFP still scopes client egress to the configured loopback address and port. D2 decides whether to add endpoint-owner identity; an identity-scoped route sets `hostLoopback: "deny"` and `containment.config.network.allowedProxyPeer`. D3 is resolved by the Windows peer evidence to UI enabled, retaining clipboard none and input injection off. The UI-disabled control cases remain useful diagnostics, not a production backend choice. Git Bash cannot start in MXC and requires its independently admitted fallback/shell route. See [peer results](#windows-peer-results-at-f19e1dc87). [U2] [A10] [A14]

The shape is defined by `T:dist/v1/types.d.ts:191–212,375–386,409–455`; the SDK selects wire contract `1.0.0` (`T:dist/v1/contract-version.js:4`). Do not put `version`, `process.env`, `process.cwd` or top-level `runtimeConfig` on this public request. `LifecycleConfig` defines `destroyOnExit: true` and `preservePolicy: false` defaults (`T:dist/v1/types.d.ts:40–45`), but **ContainerRequest does not expose a lifecycle field**. The adapter explicitly emits `destroyOnExit: true` and `preservePolicy: !clearPolicyOnExit` (`T:dist/v1/container.js:146–164`). Use `clearPolicyOnExit: true` and verify actual teardown; do not bypass the public API to set invented fields. Never pass `options.telemetry` or request consent; the spawn boundary must assert that telemetry is omitted, and its test must observe the SDK argument list. [T]; `T:dist/v1/operation-options.d.ts:8–12`

Environment construction retains safe Windows runtime variables including `SYSTEMROOT` and `LOCALAPPDATA`, fresh HOME and principal temp, and required host-runtime mode. Strip secrets and caller proxy overrides, then apply only host-owned invocation proxy/CA settings. Disable default inheritance; a missing required variable fails preparation. Use Windows command-line quoting, never string interpolation of plugin arguments into a shell. `workingDirectory` must be within admitted R/W roots: worker/plugin defaults use their own admitted home/data, hooks use the existing admitted cwd, and MCP honors its configured cwd only if already reachable. Do not add cwd to the write set for compatibility. [A7] [A8] [A14] [A22]

The proxy keeps the existing owner policy: worker/plugin allowlists, MCP/user-hook model endpoints where no plugin owns them, and explicit offline holders with no inherited network permission. A proxy URL is not an allowed destination list. Bind each listener to its host-issued owner and lifetime and retain DLP-masked deny audit. [A20]

Filesystem conversion reuses `rankMxcFilesystem` after shared admission: allowed writes, allowed reads, sensitive read floor, write-deny downgrades and missing-path denies. A write deny cannot simply become a total deny when the corresponding read is admitted. A missing protected descendant must stay uncreatable, raising to the first missing ancestor only inside that holder's writable root. Add the plugin-root isolation floor and re-allow only this holder's roots. Preserve reviewed floor pierces and host-only storage exclusion. Never use the old session's aggregate live ACL grants as MXC's allow list. Fixed policy means newly appearing paths and changed deny obligations require revalidation and replacement. [A3] [A5] [A14]

### Ancestor query access for entry resolution

The production `rankMxcFilesystem` returns readwrite/readonly/denied arrays without synthesizing ancestor grants. `buildMxcShellRequest` copies them, checks that cwd lies inside a grant, and sets UI enabled; `prepareMxcShellLaunch` supplies the proxy/system environment but adds no ancestor enumeration or drive-root read. The architecture records historical interactive Node startup with UI enabled, not a general policy for resolving an entry script from an arbitrary deep directory. Do not infer that the current shell builder already solves the peer's `lstat D:\` failure. [A10] [A14] [A27]

The old probe allowed its temp run directory and runtime/SystemRoot directories, but no metadata reach to their parents. On the peer, Node main-module `realpathSync` tried the drive-root ancestor and failed before running the entry script. Proposed fix for the probe and production extension request: retain those leaf R/W roots and add only uncovered strict ancestors of cwd/script directory, runtime directory and any extra runtime read root to `containment.config.filesystem.enumeratePaths`. SDK 1.0.1 maps this to `processContainer.filesystem.enumeratePaths` and PSEC `fs_enumerate`, a query/list grant without file-content reads; it requires PSEC 1.1 support. It is broader than invisible traversal because names/metadata can be enumerated. Minimize the list and preserve protected-path policy; do not widen read roots. `T:dist/v1/types.d.ts:175–181`, `T:dist/v1/container.js:165–173,227–235` [T] [U6]

For the reported D-drive run directory the uncovered chain is the run parent, `D:\cc-verify\mxc`, `D:\cc-verify` and `D:\`; other drives add only their required ancestors. The new probe emits `filesystemPolicy.ancestorAccess: "query-enumerate-only"`, the exact `enumeratePaths`, `driveRootRead: false` and `entryVariant: "script-file"`. Both root read and root write grants are refused; unsupported enumeration fails before spawn rather than silently broadening access. The original entry script/arguments remain unchanged, including the grandchild file entry. The narrow list-only form exists, so this revision does not switch to `-e`/stdin or `--preserve-symlinks-main`. Whether this metadata policy is sufficient on the peer remains a new native measurement, not a passed result. [U6]

**Strict policy choice: respawn.** Do not pre-authorize the union of all roots a holder might use in later turns. It retains authority after a folder/turn grant ends and makes cancellation unable to revoke that access. A hash of the admitted canonical plan determines whether reuse is possible; every turn lease ends authority even if its path hash matches the next turn. Stop admission first, cancel, terminate the old container, then publish the replacement. If termination cannot be established, refuse replacement and keep the old lease quarantined; never claim revocation or switch its backend. Long-lived plugin/server roots remain incarnation-scoped; only explicitly turn-bound worker authority ends with the turn. This is a proposed stricter lifetime rule, not the current account-wide ACL behavior. [A1] [A2] [A3] [A11]; `T:dist/v1/container-process.d.ts:31–38,85–95` [T]

### Transport feasibility and holder ownership

The plugin child's framed stream protocol already exists off the current Windows relay path. Adapt the transport interface to SDK Readable/Writable streams; retain framing limits, sender binding, subscriptions, HostApi gates and handshake. Never treat a native PID as proof of recipient authority. MCP/hooks naturally fit these streams. Acquire **all three streams before calling `wait()`**: otherwise SDK wait closes untaken stdin and drains untaken output, and later output access throws. [A4] [A7] [A9]; `T:dist/v1/container-process.d.ts:31–38,68–95` [T]

Delegated workers are different: their public handle returns `socketPath: null` for TCP, and stdin is a liveness pipe rather than a command channel. Recommended design: a generic host-runtime bridge **inside the same container** starts the worker and forwards its local TCP control byte stream over a separately framed host stream, while preserving the worker's stdin liveness and stdout/stderr events. The host presents the existing HTTP client a transport adapter; a plugin must not choose a host port to bypass policy. This bridge needs protocol versioning, bounded frames/backpressure, an authenticated host-selected endpoint and destination ownership checks. It is new implementation work, not an existing SDK feature; **feasibility is uncertain**. The pinned networking guide reports direct loopback bypasses blocked in proxy mode, so even same-container `127.0.0.1` traffic may not survive. Measure the bridge under the exact proxy policy, then prove framing/backpressure and worker compatibility before selecting this path; do not replace it with an arbitrary host-loopback exception. See D1. [A1] [A2] [A12] [U2]

The supervisor retains a strong `MxcProcess` reference while its holder is admitted; there is no default SDK execution deadline. Map hooks and tool ceilings to `TOOL_TIMEOUT_POLICY` and abort cancellation, and let admitted long-lived servers/workers run until release. On stop/revocation/reset/shutdown: remove authority markers, end input, call `kill()`, await terminal settlement while draining output, then `dispose()` in final cleanup. Handle both a synchronous `dispose()` error and rejection of the wait promise after disposal; surface cleanup failure. `dispose()` initiates asynchronous cleanup, so returning from it alone is not proof of death; use successful `wait()` for an ordinary stop and a native lifecycle observation for abnormal disposal. Keep home/temp and egress leases until termination is established. Do not manufacture a `ChildProcess` cast: adapt consumers to a common owned-process contract with streams, completion, termination and cleanup. [A1] [A8] [A16]; `T:dist/v1/types.d.ts:442–455`, `T:dist/v1/container-process.js:63–75,150–190` [T]

Authority removal immediately blocks new HostApi effects, worker sends and publication of the old marker. Report teardown as pending until native terminal completion and output draining establish death; only then release listener/home and permit replacement. Failed or timed-out kill leaves that holder non-ready, with cleanup still owned by the shutdown manager. A caller timeout alone does not establish death. [A1] [A8]

Both main-process death and supervisor death must end all associated containers and descendants, including a worker ignoring EOF. Main owns a liveness channel to the supervisor; EOF triggers native teardown. Main also retains a kill-on-close job binding for the supervisor and its relevant process tree where compatible with PSEC, established before admission. A watchdog outside the supervisor observes child/grandchild death; a crash cannot report its own cleanup. Job/PSEC compatibility and forced main/supervisor termination are native release tests. If this chain cannot be proven, the holder is non-ready; SDK object ownership alone is insufficient. [A19]; `T:dist/v1/container-process.d.ts:31–35` [T]

Choose SDK JS **in a dedicated supervisor process, not Electron main**, for persistent extension processes: `spawn()` returns live native streams plus `wait`, `kill`, `dispose`, and native lifecycle ownership. Retain `wxc-exec` for the current shell route and boot probe. ### Placement and DLL loading

`spawn()` loads `mxc_ffi.dll` through in-process `koffi`; placing it in main would let a native fault terminate the entire host. Main sends sealed launch plans to a dedicated supervisor and owns its liveness/termination; the supervisor owns native handles and streams. IPC is bounded, authenticated, generation-bound and inaccessible to extension code. An individual supervisor crash fails its holders and removes their capability markers; no backend retry is allowed. This extra process/stream forwarding is part of the implementation estimate. `T:dist/native-library.js:8,48–80` [T]; [A19]

Before the first addon/SDK load, a native supervisor bootstrap must call `SetDefaultDllDirectories` with only SYSTEM32 plus explicitly registered verified installed native directories, then `AddDllDirectory` for the selected SDK/addon/runtime payload. Exclude cwd, workspace, temp, user PATH and arbitrary adjacent directories. Verify absolute paths and hashes for every dependent DLL, including `wslcsdk.dll` if present, and reject unexpected resolved modules; scrubbing `MXC_FFI_DIR` alone is insufficient. Restricting search in main does not configure a separate process. Test a planted same-name DLL in cwd/PATH/temp without loading it; inspect the actual loaded module paths. The probe supervisor sets restrictions after loading its operator-trusted bootstrap addon; production must establish them **before** that addon, and these prototypes do not claim to validate production DLL bootstrap hardening. [U4]; `T:dist/native-library.js:48–80` [T]

Packaging requirements:

- Add exact `@microsoft/mxc-sdk` 1.0.1 to production `dependencies` and update bun.lock. Its runtime dependencies are `koffi`, `node-pty`, and `semver` (`T:package.json:61–65`); inventory resolved transitive binaries and licenses. Do not assume the launcher-only resource rule packages the SDK. [A15] [T]
- SDK loads `bin/<arch>/mxc_ffi.dll` through `koffi`, whose own `.node` addon also needs unpacking. Explicitly package the SDK JS and unpack its selected DLL/native payload plus the resolved FFI addon under `app.asar.unpacked`; preserve their directory relationship. Existing node-pty unpack rules remain. Do not ship unused backend binaries by default: determine dependent DLLs with a real packaged load, not a filename guess. `T:dist/native-library.js:8,18–29,48–80` [T]; [A15]
- The SDK's loader also searches source-build locations and honors `MXC_FFI_DIR`. Production must scrub that override, verify the resolved path remains the installed unpacked package tree, and refuse a hash mismatch **before import/load**. The supervisor bundle must externalize the SDK if package-relative resolution is required; validate the emitted bundle and packaged lookup. Never let a developer build DLL become a silent production fallback. `T:dist/native-library.js:48–80` [T]; [A15]
- Keep the tarball SHA-512, MIT license SHA-256, and per-architecture launcher SHA-256 pins shared with fetch/boot/packaging. Expand the same integrity manifest to the SDK JS payload, selected `mxc_ffi.dll`, FFI addon and transitive runtime artifacts. Record locked resolutions and per-arch byte hashes; an npm lock integrity check alone is not an installed-byte check. Verify staged and installed payloads, including app.asar.unpacked; retain the administrator-writable installation assumption and developer-checkout limitation. [A10] [A15]; `T:dist/native-library.js:77–80` [T]
- Include SDK MIT text under license notices plus resolved FFI/pty/transitive notices, update `THIRD-PARTY-NOTICES.md` and `resources/licenses/mxc/` from the resolved dependency inventory, and verify actual installer contents. The measured launcher license SHA-256 is `d9a1b1e30d633d5732ea18e3cba9538d293ebc53e1a9e4e96ab739e0c5c4f1cb`, unchanged from the existing pin; that does not prove all new dependencies are covered. [A10] [A15]; `T:LICENSE.md:1–21`, `T:package.json:61–65` [T]

## 4. Host selection and readiness

Current `windows-sandbox-plan.ts` makes MXC a candidate only for requested shells, assigns extensions `srt-win | none`, and keeps process-wide confinement false for proxy-only startup. The shared substrate type does not yet admit MXC extensions. Extend the planner and shared validators/producers/consumers together; do not merely mark ASRT globally active. [A13] [A17]

Readiness is a conjunction, not a version/build predicate: verified installed SDK/DLL/addon; BaseContainer probe; dry-run of the exact holder request; actual SDK spawn under the intended runtime with the selected D3 UI policy and admitted cwd/env; stdin/stdout/stderr round-trip and clean termination; and the D2 endpoint-isolation/optional peer-identity probe. D3 requires UI enabled; validate the ancestor query policy and actual runtime start instead of retrying with UI disabled. Probe deadline comes from a centralized `TOOL_TIMEOUT_POLICY` entry. On deadline, reject queued starts or choose the already-ready 0.0.80 route before any holder is admitted. Never leave a queued operation waiting indefinitely or silently execute it unconfined. Initial degraded-host behavior applies only after a settled no-backend plan. D1-dependent workers additionally require the bridge capability proof. [A10] [A13] [A21]

Proposed planner for plugin children, delegated workers, MCP stdio and plugin hooks, evaluated independently of `osToolSandbox` when `pluginWorkerConfinement` is requested. User hooks remain on `admittedPlan ?? getHostShellExecutionPlan()` as recommended by D4, preserving the plan identity/generation recheck and existing enablement rules. A shared low-level helper is not authority to change that selector. [A9] [A25]

The planner must expose the requested backend, selected backend and a visible readiness/fallback reason per runtime/holder class. D3 is resolved to UI enabled: report `ui-enabled` and the GUI exposure. An ancestor-policy or startup failure is a pre-admission readiness failure; any selection of 0.0.80 must display its actual reason, rather than silently making every extension stay on the old substrate. Never retry a failed admitted MXC holder under another backend. Bash-class holders are not MXC-ready under either UI setting; retain the independently admitted srt-win/shell-plan route with a visible incompatibility reason. [A10] [A13]; see [peer results](#windows-peer-results-at-f19e1dc87).

Extension plan:

| Host state | Extension selection and report |
| --- | --- |
| Setting off | No extension confinement; unchanged opt-in behavior. |
| MXC checking | Queue extension starts until the dedicated SDK/native-runtime + actual extension request probe settles; readiness says checking. Do not admit a temporary unconfined holder. |
| Actual SDK/container/transport probe succeeds | New holders use MXC even if srt-win is absent. ASRT can start proxy-only for their invocation listeners. Report MXC and its proven dimensions per holder. |
| MXC host capability unavailable, srt-win ready | New holders use pinned 0.0.80 fallback and existing shared-account disclosure. No 0.0.81 initialization. |
| Both unavailable | Preserve existing Windows degraded-start behavior and warning, report extensions unconfined; grant no sandbox-based permission relaxation. |
| Selected MXC holder fails to spawn or loses its handle | Fail that operation/stop holder. Do not retry under srt-win or unconfined. A later independently admitted holder can use a newly evaluated host plan only after explicit session reinitialization. |

These are design requirements replacing the current planner outputs, with the existing Windows degraded-host policy retained. “Never mix within one holder” covers children, hooks and delegated descendants: the holder's container tree cannot contain an independently srt-wrapped child or host-spawned escape. A selected MXC parent whose required transport cannot run fails admission. Any unavailable-runtime fallback is decided before creating the holder; it never changes a live holder. D3 does not authorize UI-disabled fallback as the default. Global ASRT state must not make the persistent PTY or unrelated tools appear MXC-confined. [A10] [A13] [A17]

Settings/Doctor should distinguish requested, checking, selected and active; backend version and unavailable reason; fallback shared-account filesystem reach; and network identity strength actually established by the probe. Update `SandboxWindowsSubstrateInfo.extensions`, extension egress identity, readiness diagnostics, plugin/MCP capability markers, localized messages, fixtures and serialized validators in one contract change. A marker is published only after native spawn and transport setup succeed and is removed at authority revocation. Each actual tool/effect still enters the permission pipeline. [A4] [A7] [A13] [A17]

## 6. Permission decision tree

The order in [permission-decision-tree.md](../architecture/permission-decision-tree.md) stays unchanged: admission/hooks/deny → forced-question targets → ask/allow rules and remembered grants → tool kind and sandbox evidence → mode/human/reviewer. Plugin effects still pass independently for the actual effect; headless asks deny. No decision node or approval scope is replaced by MXC. The evidence consumed at the sandbox/capability node changes from shared-account confinement to a specific proven holder; if evidence is absent, no read relaxation or sandbox-auto is granted. [A16] [A17]

No new folder permission or remembered grant is requested merely to create a container or restart with an already-admitted envelope. Expansion still asks under existing rules, and forced questions remain one-time. A restart reports interrupted work and requires a fresh action to repeat effects; it never treats a previous completed approval as permission to replay. A backend unavailable warning/readiness indicator changes, not the card ordering. D2 may require a security disclosure; it cannot authorize past deny rules or silently switch modes. [A2] [A16]

## 7. Owner decision points

**D1 — delegated worker transport.** (1) Generic in-container TCP-to-framed-stdio bridge (**recommended only if the proxy-mode prototype succeeds; feasibility uncertain**); (2) version the worker contract to require stdio control and migrate/exclude TCP-only workers; (3) use a direct host TCP exception, a deliberate network-policy change. Proxy mode can block direct loopback bypasses, so a working non-proxy loopback server is not sufficient evidence for option 1. [A1] [A12] [U2]

**D2 — proxy-owner identity.** (1) Add identity-scoped peer binding: either an unpackaged AppContainer proxy **plus an administrator-owned firewall rule**, conflicting with the current no-UAC/no-admin invariant, or MSIX/sparse-package identity with signing, registration, deployment/update/rollback and firewall-manifest work. Moving proxy execution out of Ave main also requires authenticated per-invocation listener ownership, DLP/credential handling and audit transport across the supervisor/proxy boundary. Planning costs: unpackaged AppContainer plus administrator firewall/installer work adds roughly **4–7 implementation days and 2–3 validation days**, plus an explicit exception to no-admin installation; signed MSIX/sparse identity adds roughly **5–9 implementation days and 2–4 validation days**, plus signing/registration/deployment lead time. Neither is a flag-only change. (2) Keep the current identity-less endpoint-scoped WFP route (**recommended for the current unpackaged NSIS/no-admin contract**), disclose that Windows cannot authenticate who owns the endpoint, bidirectional loopback is requested and inbound depends on host Firewall. (3) Require peer identity and choose 0.0.80 before holder admission where it cannot be provided. Option 1 requires explicit approval for its installation/signing implications; do not quietly introduce elevation or package identity. Native endpoint-isolation tests remain required for every option, consistent with `kernel-channel`. [A10] [A13] [A26] [U2]

**D3 — resolved: UI enabled.** The owner accepts UI enabled like shells, with clipboard none and input injection off, based on the Windows peer measurements below. UI-disabled Electron exits `0x80000003` without output, and PowerShell exits `0xc0000142`; retaining UI disabled would route every tested holder to srt-win. UI-enabled PowerShell starts successfully. UI-enabled Electron reaches Node module resolution but needs the ancestor query fix; this failure does not reopen the UI-off choice. Report `ui-enabled` and its exposure; contained windows remain untrusted. [A10]; see [peer results](#windows-peer-results-at-f19e1dc87).

**D4 — user hook selector.** (1) Unify user hooks under the extension-confinement selector, changing which setting/plan authorizes them; (2) keep the admitted/live **host-shell plan** (**recommended**, preserves behavior). Select option 2 in this design: plugin hooks follow extension confinement, user hooks keep their existing shell setting, plan identity and generation checks. PowerShell uses the resolved UI-enabled posture when its admitted plan selects MXC. Git Bash fails in both UI modes: a bash-form hook must stay on its independently admitted srt-win 0.0.80 or existing shell-plan route and must never be advertised or retried as MXC-capable. This selection precedes holder creation; it does not let an MXC parent launch a fallback child outside its own confinement. The shared bundled helper must not replace the selector. See [peer results](#windows-peer-results-at-f19e1dc87). [A9] [A25]

Respawn instead of future-rights union and the dedicated native supervisor are design selections, not new permission cards. The permission decision order and settings defaults do not change. [A13] [A16]

### Rollback

Before release, retain a tested 0.0.80 fallback installation and separate integrity manifests for the old/new payloads. To roll back: close admission, stop all MXC holders and independently verify their descendants are gone, release their listener/policy/home resources, then restart Ave with the previous release or a new boot plan selecting 0.0.80. Never change a live holder's substrate, never run both backends for its descendants, and never remove another session's ACL roots or helper state. If cleanup cannot be verified, report the holder non-ready and require session shutdown; do not claim rollback complete. The SDK default policy cleanup is not an installed-ACL cleanup guarantee for the fallback. [A5] [A8] [A13]; `T:dist/v1/types.d.ts:40–45`, `T:dist/v1/container-process.js:164–190` [T]
