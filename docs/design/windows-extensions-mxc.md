## 2. Proposed common spawn contract

Use one host-owned immutable launch plan per holder incarnation, selected after existing permission admission: owner identity, backend, session/generation, canonical R/W/deny objects, executable/arguments, cwd, stripped environment, transport and egress lease. Revalidate admission, root identities and the owner incarnation immediately before spawn. Backend choice is sealed with that plan. Preserve the shared filesystem admission and private-storage exclusions; a conversion error refuses that launch. These requirements carry the existing admission boundaries into the fixed spawn request. [A2] [A3] [A5]

The dedicated supervisor described in §3 owns native SDK calls. For MXC, use `spawn` from `@microsoft/mxc-sdk/v1` with this **typed** shape, not the raw CLI JSON fields:

```ts
{
  command: quotedExecutableAndArgs,
  containment: { type: "processcontainer", config: { filesystem: { enumeratePaths: admittedAncestorQueries } } },
  workingDirectory: admittedCwd,
  environment: strippedEnvironment,
  inheritDefaultEnvironment: false,
  filesystem: {
    readwritePaths: ranked.readwrite,
    readonlyPaths: ranked.readonly,
    deniedPaths: ranked.denied,
    clearPolicyOnExit: true,
  },
  network: {
    egress: { default: "deny" },
    ingress: { default: "allow", hostLoopback: "allow" },
    runtimeConfig: { networkProxy: invocationProxyUrl },
  },
  ui: { disable: false, clipboard: "none", allowInputInjection: false },
}
```

The example uses identity-less proxying: WFP still scopes client egress to the configured loopback address and port. The owner decided D2 option 2 on 2026-11-01: retain identity-less endpoint scoping with disclosure, omit `allowedProxyPeer`, and require `ingress.hostLoopback: "allow"`. D3 was decided by the owner, 2026-11-01 (evidence: [peer startup measurements](#windows-peer-results-at-ca22a44ab) and [PowerShell controls](#windows-peer-results-at-f19e1dc87)): UI enabled, retaining clipboard none and input injection off. The UI-disabled control cases remain useful diagnostics, not a production backend choice. Git Bash cannot start in MXC and requires its independently admitted fallback/shell route. See [peer results](#windows-peer-results-at-f19e1dc87). [U2] [A10] [A14]

The shape is defined by `T:dist/v1/types.d.ts:191–212,375–386,409–455`; the SDK selects wire contract `1.0.0` (`T:dist/v1/contract-version.js:4`). Do not put `version`, `process.env`, `process.cwd` or top-level `runtimeConfig` on this public request. `LifecycleConfig` defines `destroyOnExit: true` and `preservePolicy: false` defaults (`T:dist/v1/types.d.ts:40–45`), but **ContainerRequest does not expose a lifecycle field**. [T]; `T:dist/v1/operation-options.d.ts:8–12`

Environment construction retains safe Windows runtime variables including `SYSTEMROOT` and `LOCALAPPDATA`, fresh HOME and principal temp, and required host-runtime mode. Strip secrets and caller proxy overrides, then apply only host-owned invocation proxy/CA settings. Disable default inheritance; a missing required variable fails preparation. Use Windows command-line quoting, never string interpolation of plugin arguments into a shell. `workingDirectory` must be within admitted R/W roots: worker/plugin defaults use their own admitted home/data, hooks use the existing admitted cwd, and MCP honors its configured cwd only if already reachable. The proxy keeps the existing owner policy: worker/plugin allowlists, MCP/user-hook model endpoints where no plugin owns them, and explicit offline holders with no inherited network permission. Add the plugin-root isolation floor and re-allow only this holder's roots. Preserve reviewed floor pierces and host-only storage exclusion. ### Ancestor query access for entry resolution

The production `rankMxcFilesystem` returns readwrite/readonly/denied arrays without synthesizing ancestor grants. `buildMxcShellRequest` copies them, checks that cwd lies inside a grant, and sets UI enabled; `prepareMxcShellLaunch` supplies the proxy/system environment but adds no ancestor enumeration or drive-root read. The architecture records historical interactive Node startup with UI enabled, not a general policy for resolving an entry script from an arbitrary deep directory. Do not infer that the current shell builder already solves the peer's `lstat D:\` failure. [A10] [A14] [A27]

The old probe allowed its temp run directory and runtime/SystemRoot directories, but no metadata reach to their parents. On the peer, Node main-module `realpathSync` tried the drive-root ancestor and failed before running the entry script. Measured probe fix and required production extension policy: retain those leaf R/W roots and add only uncovered strict ancestors of cwd/script directory, runtime directory and any extra runtime read root to `containment.config.filesystem.enumeratePaths`. SDK 1.0.1 maps this to `processContainer.filesystem.enumeratePaths` and PSEC `fs_enumerate`, a query/list grant without file-content reads; it requires PSEC 1.1 support. It is broader than invisible traversal because names/metadata can be enumerated. Minimize the list and preserve protected-path policy; do not widen read roots. `T:dist/v1/types.d.ts:175–181`, `T:dist/v1/container.js:165–173,227–235` [T] [U6]

For the reported D-drive run directory the uncovered chain is the run parent, `D:\cc-verify\mxc`, `D:\cc-verify` and `D:\`; other drives add only their required ancestors. The new probe emits `filesystemPolicy.ancestorAccess: "query-enumerate-only"`, the exact `enumeratePaths`, `driveRootRead: false` and `entryVariant: "script-file"`. Both root read and root write grants are refused; unsupported enumeration fails before spawn rather than silently broadening access. The original entry script/arguments remain unchanged, including the grandchild file entry. The narrow list-only form exists, so this revision does not switch to `-e`/stdin or `--preserve-symlinks-main`. The peer rerun at ca22a44ab cleared the drive-root EPERM and started the UI-enabled runtime with this policy; read-only before/after host DACL snapshots were identical. Production must synthesize query/enumerate-only ancestors up to the drive root on every involved volume without host DACL augmentation. This is measured for the reported paths/runtime, not arbitrary reparse layouts. Whether `fs_enumerate` cascades into subdirectories is **unverified**. With the default user-profile tmpdir, ancestor grants can expose sibling names/metadata under the profile and its parents; temp HOME environment overrides do not remove that exposure. Prefer a dedicated staging/temp tree, minimize roots and disclose residual name exposure; test descendant enumeration before making a narrower privacy claim. [U6]; see [rerun evidence](#windows-peer-results-at-ca22a44ab).

### Transport feasibility and holder ownership

The plugin child's framed stream protocol already exists off the current Windows relay path. Adapt the transport interface to SDK Readable/Writable streams; retain framing limits, sender binding, subscriptions, HostApi gates and handshake. Never treat a native PID as proof of recipient authority. MCP/hooks naturally fit these streams. Acquire **all three streams before calling `wait()`**: otherwise SDK wait closes untaken stdin and drains untaken output, and later output access throws. [A4] [A7] [A9]; `T:dist/v1/container-process.d.ts:31–38,68–95` [T]

Delegated workers currently return `socketPath: null` for TCP, and stdin is a liveness pipe rather than a command channel. The same-container TCP-to-stdio bridge (D1 option 1) is **disproven under the tested identity-less endpoint-scoped proxy policy**: the runtime starts but its connect fails `EACCES`. The owner decided D1 option 2 on 2026-11-01: version the worker contract to require native stdio control, as the plugin child can directly use SDK `standardInput`/`standardOutput`. Retain EOF liveness, bounded framing, subscriptions, stdout event demultiplexing, stderr diagnostics, backpressure, cancellation and recipient checks; reserve protocol stdout so arbitrary logs cannot become frames. Add explicit transport negotiation and a bounded send/request API because the current handle only exposes output subscriptions and stop. Update the spec/handle, dispatcher allowlist, wire types/schema, child stub, host factory and released contract copies together at an app release tag. Each worker implementation/client must actually implement the new protocol; changing `socketPath` or adding a wrapper cannot turn an HTTP server into stdio control. For an MXC-selected owner, require a declared stdio control v1 worker contract. A TCP-only, missing or incompatible declaration deterministically refuses the worker spawn before process/container creation with `WorkerTransportUnsupportedError` (wire code `worker-transport-unsupported`), plus clear update/migration guidance. Keep the existing parent incarnation on MXC; do not start a fallback child, reselect its backend or retry outside containment. This generic contract predicate uses no plugin-ID branches. Refusal preserves the sealed owner plan and avoids weakening the network policy; the initial host-unavailability fallback in §4 is a separate decision. D1 option 3 would deliberately change network policy and is not recommended. [A1] [A2] [A12] [U2]; see [rerun evidence](#windows-peer-results-at-ca22a44ab).

### Placement and DLL loading

`spawn()` loads `mxc_ffi.dll` through in-process `koffi`; placing it in main would let a native fault terminate the entire host. Main sends sealed launch plans to a dedicated supervisor and owns its liveness/termination; the supervisor owns native handles and streams. IPC is bounded, authenticated, generation-bound and inaccessible to extension code. An individual supervisor crash fails its holders and removes their capability markers; no backend retry is allowed. This extra process/stream forwarding is part of the implementation estimate. `T:dist/native-library.js:8,48–80` [T]; [A19]

**Selected bootstrap:** run the dedicated supervisor under the packaged application executable with `ELECTRON_RUN_AS_NODE=1`. The packaged Electron RunAsNode fuse must remain enabled; packaging requires an explicitly enabled fuse because this supervisor cannot run without it. Before any native require, verify the installed files listed in `mxc-launcher-pins.json`: SDK `dist` JavaScript, the FFI package ESM entry chain and CJS entries, the locked nested `semver` JavaScript, the PTY package JavaScript/prebuilds, and the selected absolute bootstrap `.node`. Verify every file in the selected unpacked addon directory and SDK bin directory. Dependency resolution uses import conditions for the ESM entry and must match the pinned package roots; a regression records the actual SDK entry import graph through spawn/probe without executing native code. This covers the recorded static graph and explicitly pinned deferred artifacts, not arbitrary computed dynamic imports. Unexpected files, redirected paths, missing bytes and loader overrides refuse startup. Load that one verified addon directly as the trusted bootstrap. Immediately call `SetDefaultDllDirectories(LOAD_LIBRARY_SEARCH_SYSTEM32 | LOAD_LIBRARY_SEARCH_USER_DIRS)` and `AddDllDirectory` for the verified SDK/addon directories in this same supervisor. Only then import the SDK or load `mxc_ffi.dll`. The SDK remains external to the bundle so its package-relative resolution reaches the verified unpacked tree. No native bootstrap executable or new toolchain is added. [U4]

This explicitly trusts the verified first addon before DLL-search restrictions are installed, matching the measured bootstrap mechanism. Its pinned binary imports the system loader/security libraries; actual import paths still require native inspection. Cwd, workspace, temp, PATH and arbitrary adjacent directories are excluded from subsequent native dependency search. Packaging records the executable and adjacent runtime DLL hashes after assembly and again after signing. The supervisor verifies that installed runtime inventory before the first addon load as well. Audit all loaded module paths after bootstrap/import, after the exact-request probe and after spawn. Resolve both the allowlist and each loaded path through realpath, then normalize Windows spelling and case before comparison, including the actual system directory. Every module outside that directory, including the initial module set, must resolve to a pinned SDK/addon or recorded runtime file. WinSxS and injected EDR/IME modules outside this allowlist fail closed with `MxcIntegrityError`; system signatures alone grant no exception. Compatibility with those modules, junctions and short names remains native-unverified. These audits examine every enumerated module before diagnostics are reduced to a bounded selected-first list with the total count and a truncation flag. Diagnostic truncation never authorizes an unchecked module. These audits are snapshots, not a continuous module-load monitor. No unchecked initial baseline is admitted. A planted resolved module refuses the launch; no alternate SDK or backend is retried. Restrictions are process-local and are never assumed to inherit from main.

**Trust assumption:** installation contents may belong to the signed-in user. Hash verification detects drift and planting at verification time; it does not defend against that same user racing replacement of the application, JS, pins or native files between verification and loading. The current installer configuration has `nsis.perMachine: true`; this slice does not change that setting and does not rely on administrator-only writes as the bootstrap security premise. Developer checkouts are not accepted by the public native spawn path. A real packaged load on each architecture must inspect resolved modules and planted-DLL cases before native readiness is claimed.

The common primitive creates one supervisor per holder incarnation. A separate inherited pipe delivers a fresh 256-bit authentication key and stays open for owner liveness; the key is absent from argv, environment and container input. Length-bounded control frames carry a generation, monotonic sequence and direction-bound HMAC. Stream chunks are at most 32 KiB, frames at most 64 KiB, and at most four outgoing frames can wait for pipe backpressure. Stdout is reserved for authenticated frames; diagnostics stay on bounded stderr. EOF on the liveness pipe starts teardown even if the control stream is backpressured. Main closes it immediately on disposal as well as on death. Supervisor control standard handles and the fd 3 key/liveness handle are explicitly marked non-inheritable before SDK spawn. The latter is resolved by the running executable’s exported `uv_get_osfhandle(3)`, without loading another runtime library; a missing export or handle-protection failure produces `MxcCapabilityUnavailableError`. Native verification must still inspect the SDK child handle whitelist, including that extra descriptor.

Before SDK import/spawn, the supervisor creates a kill-on-close job, disables handle inheritance, and assigns itself to the job without breakaway flags. It retains the job handle until process exit; the kernel closes it on a native fault or forced termination, covering inherited descendants. Ordinary disposal ends input, kills, drains output, awaits native terminal settlement and disposes, then returns an authenticated terminal receipt. After spawn resolves, the supervisor retains a non-inheritable query/synchronize process handle and sends its PID and handle in an authenticated `native-created` receipt. Main acknowledges only after its synchronous lifecycle observer can duplicate the process object; the supervisor retains its handle through that acknowledgement, including during cancellation. The packaged diagnostic main retains its duplicate until the external controller has checked the object and can independently observe terminal signaling. No lifetime job handle is duplicated. Missing acknowledgements remain bounded by owner-EOF teardown and its cleanup watchdog. Main accepts successful termination only with that receipt and a clean supervisor exit. Authenticated pre-container failures retain distinct integrity, capability-unavailable, contract and supervisor-lost errors even when the supervisor exits nonzero. The supervisor announces native creation before calling spawn; a deadline or missing terminal receipt after possible creation reports cleanup as unverified. Startup cancellation sends stop while keeping liveness open through the native-created/native-observed handshake; a failed stop-frame send requests EOF teardown. Actual owner loss still releases an outstanding observation. After readiness confirms observation, disposal closes liveness immediately so backpressured control input cannot block teardown. This preserves the container process pin across cancellation, with forced termination only at the cleanup deadline. Job/PSEC nesting and independent descendant-death observations after main/supervisor kill remain native-unverified on both architectures; this code does not itself publish native readiness or route existing holders.

The [packaged native verification harness](../../tools/mxc-probes/README.md#packaged-extension-process-acceptance) invokes the public primitive under a locally packaged runtime. It records bounded admitted module diagnostics with their full count and truncation flag, uses authenticated creation/cancellation observations, compares the actual fd 3 pipe object with descendant handles, and checks independently pinned process objects after disposal or main/supervisor termination. Its planted-DLL control mutates only a temporary package copy. These are executable acceptance checks, not recorded Windows results; no holder becomes ready merely because the harness is present.

Package manifests use the required semantic pins for `name`, `version`, `main`, `exports`, `type` and `imports`, including field absence and condition declaration order; descriptive/build metadata may be removed by packaging. Their raw source hashes remain archive/staging audit inputs. Every JavaScript, addon, DLL and executable entry still requires its exact SHA-256. The locked nested semver tree is copied explicitly through Windows extra resources into its pinned unpacked path because dependency collection can hoist it. PTY `.pdb` files are a declared debug-symbol category, excluded from runtime pins and packages because they are not loaded; no executable hash is skipped.

The diagnostic entry is included only when `AVE_MXC_VERIFICATION_BUILD=1` is set at build time. Ordinary builds remove stale probe output, and packaging on every platform rejects a verification build or stray probe entry without that explicit flag. Installed SDK inventory permits only pinned runtime files and documented archive extras: declarations and source maps under `dist`, root README/license text, the named unused backend files in `SDK_INSTALLATION_AUXILIARIES`, generated `dotnet/NativeMethods.g.cs`, and provenance metadata under `bin/<arch>/_manifest`. Nested runtime dependencies are inventoried against their pinned roots as well; the locked semver package additionally permits its LICENSE, README and `range.bnf`. The package manager’s named semver command shims in nested `.bin` are allowed as installation extras; symlinks must resolve to the pinned semver command. That shim directory is excluded and pruned from packages. Unknown nested dependency files are refused. Packaged native directories still reject every unpinned file.

## 4. Host selection and readiness

The shared selection/disclosure fields and admission API are documented in the
[extension backend policy contract](windows-extension-policy-contract.md). Its
plan is distinct from a process-active marker and retains native verification
as a separate release gate.

Current `windows-sandbox-plan.ts` makes MXC a candidate only for requested shells, assigns extensions `srt-win | none`, and keeps process-wide confinement false for proxy-only startup. The shared substrate type does not yet admit MXC extensions. Extend the planner and shared validators/producers/consumers together; do not merely mark ASRT globally active. [A13] [A17]

Readiness is a conjunction, not a version/build predicate: verified installed SDK/DLL/addon; BaseContainer probe; dry-run of the exact holder request; actual SDK spawn under the intended runtime with the selected D3 UI policy and admitted cwd/env; stdin/stdout/stderr round-trip and clean termination; and the decided D2 endpoint-isolation probe (no peer-owner authentication claim). This predicate never authorizes a backend change for an already-admitted parent. Never leave a queued operation waiting indefinitely or silently execute it unconfined. Initial degraded-host behavior applies only after a settled no-backend plan. D1-dependent workers require the versioned stdio contract and a migrated client/runtime; the bridge failed the native gate. [A10] [A13] [A21]

The planner must expose the requested backend, selected backend and a visible readiness/fallback reason per runtime/holder class. D3 is resolved to UI enabled: report `ui-enabled` and the GUI exposure. ### Rollback

Before release, retain a tested 0.0.80 fallback installation and separate integrity manifests for the old/new payloads. To roll back: close admission, stop all MXC holders and independently verify their descendants are gone, release their listener/policy/home resources, then restart Ave with the previous release or a new boot plan selecting 0.0.80. Never change a live holder's substrate, never run both backends for its descendants, and never remove another session's ACL roots or helper state. If cleanup cannot be verified, report the holder non-ready and require session shutdown; do not claim rollback complete. The SDK default policy cleanup is not an installed-ACL cleanup guarantee for the fallback. [A5] [A8] [A13]; `T:dist/v1/types.d.ts:40–45`, `T:dist/v1/container-process.js:164–190` [T]
