## Boundary repairs with unchanged outcomes

- Original-source parsing is reused only within one decision. The path walker and risk tokenizer validate the supplied command label and AST root text against the requested source; mismatches throw. The path walk still charges the original tokens and nested executed literal code to the same complete-input budget. The independent one-parse assertion and existing timing limits remain unchanged.
- Permission path evidence no longer inherits a whole-command write effect for opaque program data, executable loading or recognized read sources. Actual redirects, output options, native destinations and implicit metadata writers remain writes. Copy, move and archive source roles come from the existing command-policy records. Independent mutation-oracle failures were fixed in those producers, not by changing the oracle.
- Native search flags and patterns are data, and file-backed search options are reads; this does not confer read-only execution proof. Output redirections remain independently writable effects. New cases retain native suffixes, stop-parsing syntax, protected output and unknown output controls. Native copy utilities use their own slash-option roles, preserving protected destinations after flags, extra targets, log outputs and unknown-source option-injection evidence.
- Evidence-only Windows inspection avoids execution-only validation whose result was discarded. Execution validation remains in its actual enforcement branch; lexical/canonical admission, protected, secret and escape facts are still collected through the decision-local evidence matcher. Existing platform timing assertions are retained rather than claiming a speedup from source inspection.
- The mandatory OS write-deny union removes only literal descendants already covered by a retained literal ancestor, after resolving lexical and physical targets. Host composers supply inherited absolute nonglob denies that they also emit in the final union. External physical targets, routing-link identity, globs, missing-ancestor records and write-root narrowing remain protected. Windows retains the full generated set where later ACL narrowing can omit inherited entries. Semantic coverage assertions replace redundant literal membership assertions; three-platform union equivalence, exact external-target checks, malformed-authority denials and a long-path composer case retain the unchanged policy-size ceiling.
- Approval-expiration tests now advance `Date` with their fake timeout clock. Exact deadline, pending state, late-answer refusal, audit attribution, no execution and no durable save assertions are unchanged.
- Broker timing and cancellation tests wait for explicit transport or image-decode entry before advancing their existing policy budgets. They do not add sleeps, timing margins or synthetic receipts. Completion, cancellation and metadata assertions remain unchanged.
- Prepared host-environment assertions capture evidence while the issued handle is live. They require identical execution-owned environment identity, exact key sets, pinned working directory and stripping of a synthetic private marker, without dumping environment values or reopening a disposed capability.
- The headless invocation-cwd alignment fixture explicitly selects auto and loads its actual project rule scope before direct reviewer dispatch. It still requires one low-review allow, the exact canonical invocation cwd, an ambient-cwd negative and exact enforcement-path agreement.
- The bootstrap settings double supplies the existing change-subscription method and disposer. Integration ordering and headless service-connection assertions are unchanged.
- The rule/judge design document is no longer a runner-fixture input: its case table is independent data and no source reader names or reads that document. Removed only its stale consumed/reader registry entries and corrected its prose claim. Exact registry/source equality tests remain unchanged; no artificial reader reference was added.
- The workflow reader selector deliberately selects tests containing any `.github` literal. Its existing sandbox policy fixture now contains such a control-path example. The pre-push test requires that exact additional suite and admits only that additional source-test path in its selected-path assertion; selector behavior and every other reader requirement remain unchanged.

The literal evaluator fixture with an outer home-relative secret operand retains Allow via `allow-mode`, rather than a generic sandbox reason: independent secret-read evidence precedes the sandbox kind row. Exact-rule ineligibility remains asserted. This changes reason metadata, not the allowed decision; no expansion or opaque payload is executed for classification.
